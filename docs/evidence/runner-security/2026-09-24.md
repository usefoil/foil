# Mac runner security audit — 2026-09-24

Claim: persistent self-hosted Macs should receive repository code only after an
explicit workflow dispatch against a reviewed commit.

Strongest realistic failure mode: a public pull request, merge-queue entry, or
push schedules code onto a persistent Mac without an operator test window.

Evidence: workflow inspection found automatic `merge_group` on the deterministic
UI gate and Local macOS E2E, `push` on Local macOS E2E, and `pull_request` on macOS
CI eligibility. This change removes those triggers. `make test-ci-scripts` passed,
including a contract that scans every self-hosted Mac workflow and requires
`workflow_dispatch` as its only trigger. The `CI Gate` required by the main-branch
ruleset remains on GitHub-hosted runners.

Claim: the three minis currently have an encrypted disk, but their desktop and
network posture still need operator attention.

Strongest realistic failure mode: being on the local network or running under a
non-admin account is mistaken for evidence that the hosts are fully hardened.

Evidence: read-only SSH checks on `mm1`, `mm2`, and `mm3` used
`stat -f %Su /dev/console`,
`ioreg -n Root -d1 -a | plutil -extract IOConsoleLocked raw -o - -`,
`fdesetup status`, and `socketfilterfw --getglobalstate`. They reported FileVault on
and the macOS application firewall disabled on all three. `/dev/console`
reported `root` on all three; `IOConsoleLocked` was true on `mm1` and false on
`mm2` and `mm3`. SSH connectivity was present. The non-admin shell could not
inspect the Remote Login allowlist. No host setting, runner registration, or
credential was changed.

Residual risk / follow-up: an administrator should turn on the macOS firewall,
retain only required inbound services, and verify Remote Login and any Screen
Sharing/Remote Management access is limited to the intended management account
and host. Confirm connectivity after each change. Keep the desktops locked
outside supervised UI-test windows. The runner runbook requires a separately
authorized maintenance window for host or service changes.
